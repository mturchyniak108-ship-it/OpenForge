# OpenForge Development Workflow

## Source of truth

GitHub is the source of truth.

Do not maintain undocumented machine-local versions of OpenForge.

## S26 workflow

1. Plan the feature.
2. Modify the repository.
3. Test locally.
4. Commit.
5. Push.
6. Document the change.

## Vivobook workflow

1. Pull the latest main branch.
2. Read AI_CONTEXT.md.
3. Read the relevant project documentation.
4. Inspect existing implementation.
5. Implement the assigned work.
6. Test Blender/scripts.
7. Update documentation.
8. Commit.
9. Push.

## AI rule

An AI working on the Vivobook must read the repository documentation before modifying the Blender system.

Do not assume missing architecture from the conversation.

The repository documentation takes precedence over stale conversational assumptions.
